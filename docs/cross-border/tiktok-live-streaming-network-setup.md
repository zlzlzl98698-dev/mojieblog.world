## 一、TikTok 直播风控系统的核心检测指标

TikTok 对视频推流的审查严格程度远超普通的短视频上传。其后台算法会每隔数秒对推流链路进行一次全方位的“健康体检”：

```
┌─────────────────────────────────────────────────────────────────┐
│                    TikTok 跨境直播多维审查漏斗                   │
├─────────────────┬───────────────────────────────────────────────┤
│ 1. 丢包率与抖动 │ 必须保持丢包率 0.0% · 抖动 (Jitter) < 10ms   │
├─────────────────┼───────────────────────────────────────────────┤
│ 2. ASN 与 IP 属性│ 必须识别为当地合规电信双 ISP (禁止 Hosting IDC)│
├─────────────────┼───────────────────────────────────────────────┤
│ 3. RTMP 握手协议│ 码率平稳输出 · 帧率恒定 60FPS · 拒绝剧烈降码   │
├─────────────────┼───────────────────────────────────────────────┤
│ 4. 本地物理环境 │ 手机无 SIM 卡 · 纯净当地时区 · 关闭系统 GPS    │
└─────────────────┴───────────────────────────────────────────────┘
```

1. **为什么普通中转机场做不了直播？**
   市面上几十元一个月的常规机场，其节点出口是由数百名甚至上千名用户共享的。当有其他人在同一个节点上看 4K 视频或下载大文件时，出口带宽会产生短暂拥塞，导致瞬间丢包率飙升至 5%~15%。对于网页浏览这种丢包可以自动重传，但对于 **RTMP 直播推流**，瞬间丢包会导致视频流关键帧丢失，TikTok 算法会判定为主播网络极度恶劣，自动将直播间推流权重降至冰点。
2. **机房广播 IP 的“秒级黑屏”陷阱**：
   如果出口 IP 被识别为数据中心（Data Center），TikTok 系统会判定主播使用的是境外云服务器挂机录播，直接触发“假人直播”违规警告，直接切断直播间推流信号。

## 二、OBS 直播推流网络参数黄金配置

在 OBS Studio 中，推流设置应严格遵循以下工业级标准：

```
=============================================================================
│ 视频编码器: NVIDIA NVENC H.264 (硬件编码)
│ 速率控制: CBR (恒定比特率，严禁使用 VBR 可变码率)
│ 比特率 (Bitrate): 6000 Kbps (1080P 60FPS 黄金画质)
│ 关键帧间隔 (Keyframe Interval): 2 秒 (TikTok 官方强制标准)
│ 预设 (Preset): P5 / P6 (慢速 / 较慢，保障画质细节)
│ 多准则调优: 高画质 (High Quality)
│ 配置文件 (Profile): high
=============================================================================
```

- **下行与上行带宽预留**：推流 6000Kbps 意味着本地上行带宽需稳定消耗约 6~8Mbps。为了预留 3 倍的抗抖动缓冲区，建议直播间专线独享上行带宽保持在 **30Mbps 以上**。

## 三、双 ISP 原生住宅 IP 的技术本质与核验

所谓的 **双 ISP（Dual-ISP）**，是指该 IP 地址在国际 APNIC 或 ARIN 数据库中，无论是网络提供商（ISP）还是组织归属（Organization），均显示为当地核心民用电信宽带（如美国 AT&T、Verizon、Comcast，或英国 BT，或东南亚 TM Net）：

1. 打开权威检测平台 `ipinfo.io`。
2. 检查 `type` 字段必须明确显示为 `isp`，绝不可出现 `hosting` 或 `business`。
3. 检查反欺诈数据库 `scamalytics.com`，确认欺诈分低于 **10 分**。
