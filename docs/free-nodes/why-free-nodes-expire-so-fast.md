# 深度揭秘：为什么免费节点几小时就失效卡死？防火墙探测与带宽挤兑底层技术拆解

很多网友在使用免费节点时，经常遇到这种极其崩溃的场景：
- “下午 3 点在论坛找到的订阅，测速显示绿色 120ms，打开网页飞快；”

很多人以为这只是“运气不好”或者“提供者关机了”。**实际上，这是由现代网络对抗环境中的三大底层物理与算法规律决定的**。

## 一、GFW 的协同主动嗅探与动态端口封锁

现代长城防火墙（GFW）早已不是早期单纯依赖“静态黑名单 IP 库”的笨重机制，而是演变为一套高度智能的**“分布式协同主动探测与机器学习指纹识别系统”**。

```
[公开免费节点发布] 
       │
       ▼
[GFW 自动化爬虫监控池] ──► 瞬间获取该订阅并在 60 秒内入库
       │
       ▼
[GFW 探针集群主动发起伪装握手] ──► 发送异常 TLS/TCP 试探报文
       │
       ▼
[目标服务器如实应答] ──► 确认属于翻墙代理特征
       │
       ▼
[下发动态阻断指令] ──► 目标 IP 端口被黑洞丢弃 (Timeout 诞生！)
```

### 1. 爬虫的主动监控
一旦某个免费订阅链接被公开发布在 GitHub、Telegram 或中文论坛上，防火墙的自动化爬虫程序通常在 **1 ~ 3 分钟内** 就会同样抓取到这份订阅文件，并将里面包含的成百上千个 IP 和端口录入测试队列。

### 2. 启发式主动探测
防火墙探针会模拟客户端向目标服务器发送带有特征偏置的握手报文。传统的弱加密协议（如老旧的 Shadowsocks、未开启 TLS 保护的 VMess）在面对探针的试探时，会暴露出特定的错误回包特征。一旦被确认，该 IP 的对应端口会在接下来的数分钟内被路由器路由黑洞化，导致全国所有用户瞬间失联。

## 二、极端严重的公网带宽挤兑模型（万人过独木桥）

即使某些节点侥幸没有立刻被防火墙识别阻断，它也会迅速死于**恶性并发挤兑**：

1. **廉价 VPS 的物理极限**：免费节点通常部署在最便宜的公网 VPS 上，其分配的出口带宽通常仅有 **100 Mbps 共享带宽**，甚至限制单月流量仅 1TB；
2. **万人挤占瞬间打满**：一个拥有 5,000 名订阅者的免费池，只要在晚高峰有 200 个人同时尝试打开 YouTube 视频，每人哪怕只占 2Mbps，瞬间需求就是 400Mbps，远远超出服务器的物理网卡上限；
3. **TCP 缓冲区溢出与疯狂丢包**：网卡队列被打满后，Linux 内核会开始无差别丢弃新接入的数据包，网络丢包率飙升至 **50% ~ 90%**，在用户端直接表现为所有请求握手失败、全部超时。
